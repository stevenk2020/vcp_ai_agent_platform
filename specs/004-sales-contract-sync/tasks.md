# Tasks: Sales Contract Sync

**Input**: Design documents from `/specs/004-sales-contract-sync/`

**Prerequisites**: plan.md, spec.md, research.md, data-model.md, contracts/, quickstart.md; features 001 to 003 running (`make up`); `docs/topics/sales_contract.md` read (column facts and traps)

**Tests**: Included and required (constitution Development Workflow: every task has an acceptance test; security-relevant code ships with failure-case tests). Each phase has a **Tests** block that is the acceptance test for the tasks of that phase. No automated test needs a real SQL Server: the worker is tested with `FakeSource` (T010) against a throwaway Postgres.

**Organization**: Grouped by user story (US1 to US6 from spec.md). Paths are relative to the repository root.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: can run in parallel (different files, no dependency on an incomplete task)
- **[Story]**: US1 to US6, only in user-story phases
- **[MANUAL]**: needs the operator (real SQL Server, secrets, production switch)

**How tests run**: new `make test-sync` (isolated project `platform-synctest`; subset: `make test-sync ARGS="-k guards"`), `make test-api`, `make test` (foundation), `make scan-secrets`. All stay green after every phase. Never run these against the live project; the scripts already use isolated projects (the foundation suite runs against the live stack's database, as before, and must not leave data behind).

**Decisions that must stay visible** (from plan and research): the copy has **62 of 64 columns**, `employee_code_bdd` and `employee_name_bdd` are excluded and never selected (FR-020, option A); the copy and the control tables are created by the worker from `sync/sql/control.sql` and the definition file, not by a dbmate migration (R-4, FR-016 reworded); the swap is rename-based with staging (R-5); the source is read in `READ COMMITTED` with a lock wait of the read limit, or `SNAPSHOT` only when `SOURCE_SNAPSHOT_READ=on` (R-6); never `NOLOCK`; floats become exact decimals through their shortest text (R-8).

**Safety rules for every task**: no real secret in any file, log or test output; the worker only ever sends reads to the source; do not touch the live database from tests; commit on `dev_spec_04` only, never on `main`.
